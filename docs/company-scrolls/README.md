# Company Scrolls

**Archive class:** `PROTECTED` / `DOMAIN-OBSERVATION`  

## Mission 001: Observation Before Automation
The `company-scrolls` directory is the canonical home for understanding the real-world Phanda business domain. 
Before we write code, we make a real company our teacher. We document domains before we document software.

> **Guiding Principle:** "If it isn't true for Company Scroll 001, it doesn't become a feature."

## The Pipeline of Discipline
We do not design features immediately. Every feature must travel through this pipeline:

1. **Observation:** We witness reality.
2. **Evidence:** We point to a real document or artifact.
3. **Understanding:** We separate facts from insights. We ask questions.
4. **Pattern:** We look for repetition (e.g., duplicated documents, missed deadlines).
5. **Requirement:** The pattern dictates what is needed.
6. **Feature:** Only then do we write code.

## File Structure
All scrolls follow the `TEMPLATE.md` structure and are named `[ID]-[company-name].md` (e.g. `001-company-name.md`).

## The Principle of Origin
> **Principle of Origin:** *Company Scroll 000 is reserved permanently for the founding organization that gave birth to the observation methodology. It is the historical root of the archive and is preserved as the origin of the framework. All subsequent Company Scrolls represent independent business observations that extend and validate the methodology.*
