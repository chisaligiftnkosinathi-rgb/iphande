## Repo Governance and Canonical Structure Doctrine

**Date:** 2026-05-28

---

### Core Structure (Effective Immediately)

```
docs/
  canonical/          # governs real system behavior
  checkpoints/        # sealed implementation milestones
  boundaries/         # what must not be crossed
  architecture/       # system maps and contracts
  archive/            # historical docs

experiment/
  research/           # grounded observations
  reflections/        # spiritual/symbolic thought
  drafts/             # not canonical yet
  README.md

api/
  src/
  tests/

mobile/
  components/
  screens/
  services/
  types/

tools/
  vba/
```

---

### Key Governance Rule

> Nothing in experiment/ becomes system doctrine unless promoted into docs/canonical/ or docs/boundaries/.

This protects the system from doctrinal drift, symbolic overload, and loss of implementation focus. All experimental, research, and reflection artifacts must remain structurally and procedurally separate from canonical production doctrine.

---

### Directory Purpose

- **docs/canonical/**: Official, governing doctrine for executable system behavior.
- **docs/checkpoints/**: Sealed, versioned implementation milestones.
- **docs/boundaries/**: Explicit boundaries and non-negotiable constraints.
- **docs/architecture/**: System maps, contracts, and technical blueprints.
- **docs/archive/**: Historical and superseded documentation.
- **experiment/research/**: Grounded, observed research and anthropology.
- **experiment/reflections/**: Symbolic, spiritual, or national thought experiments.
- **experiment/drafts/**: Unreviewed, non-canonical drafts.

---

### Promotion Process

Artifacts in experiment/ may only become canonical through explicit review and migration into docs/canonical/ or docs/boundaries/.
